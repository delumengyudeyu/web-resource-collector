### 新增需求的准确表述

默认优先保存当前账号权限、网络策略、来源格式和用户明确限制下，可以完整获取的最高质量版本。若最高候选失败，按确定且可解释的规则尝试下一个候选；无高清源时保存能够获取的最佳版本，并显示实际质量与原因。

## 4. 质量规则与决策逻辑

### 4.1 默认策略和定义

- 推荐且默认：`best_available`，界面“最佳可用画质”。不设隐含 1080p 上限；如果同一内容有可获取的 4K，应优先考虑 4K。
- 可选：`cap_1080`、`cap_720`，表达分辨率上限，用于用户主动控制流量；不升频/升分辨率。竖屏以短边阈值辅助选择，并保留真实宽高，不强制按横屏高度过滤。
- 可选：`data_saver`，显式节省流量；旧 low 请求映射至这一兼容行为，不伪装为最佳。
- `fallback_enabled` 默认 true。关闭时最高合规候选失败就明确失败，不偷偷切换质量。
- 质量优先于容器偏好。默认允许适合源编码的 MP4/WebM/MKV 等容器；不能仅为 MP4 而无提示丢弃更高质量来源。
- “高清”仅作分辨率档位提示，横/竖屏、方形或特殊比例都显示真实尺寸。720p/1080p/2160p 不代表内容实际清晰度保证，更不证明不是上采样。
- 来源缺少尺寸信息时标记未知，下载后用媒体探测补充；无法验证时不能显示高清或已证明最佳。

### 4.2 视频选择与失败降级

流程：排队 → 探测候选 → 筛选权限/协议/预算 → 排序 → 下载 → 合并（如需要）→ 验证 → 完成或部分成功。

1. 借助现有 yt-dlp 成熟能力探测元数据和格式，封装为可测试的质量策略模块，不重写站点提取器。探测不应下载整段媒体。
2. 把同一内容的完整音视频组合视作候选；优先保持正确时长、所选语言音轨和完整内容，不用预告片代替正片。源无音轨时明确标注，不虚构音轨。
3. 先去除不符合授权、严格网络策略、DRM、显式分辨率上限及已知硬预算的候选，再排序。优先来源/提取器明确质量信息及有效分辨率；同档再综合帧率、编码、音轨和可靠码率。不要跨编码直接用码率大小断言质量。
4. 排序和比较依据需可解释；对未知或相互不可比较的候选标记不确定，不宣称绝对最优。HDR/SDR、不同语言与剪辑版本应保留区分，默认不擅自转色或换语言。
5. 临时网络错误、429、5xx：在同一候选内有界重试并尊重 Retry-After，不立即降清晰度。401/403 先区分会话失效、签名过期、格式权限受限；可在原授权会话与固定出口内有限刷新地址。
6. 候选确实不可用、特定格式受限或符合预算的较低候选存在时，按排序继续尝试。整个任务共享有限尝试次数和时间/存储预算，禁止无限循环。
7. 代理不可用：停止任务，不降画质掩盖网络故障，不直连。用户取消、磁盘保留空间不足或确定为整个资源无授权：停止，不盲目遍历。
8. 音视频分离时下载后本地无损封装合并；不得把未合并的视频轨、音轨或单独字幕登记为完整视频。合并失败要保存准确状态与可用证据，是否尝试合规的合并格式候选需有明确记录。
9. `bestvideo*+bestaudio/best` 可作为提取器的选择工具，不是“任何下载失败都会自动转下一档”的保证。必须有实际失败场景验证应用层策略。
10. 正式保存前检查容器可读性、宽高、音视频流、时长、缺失片段与哈希。不能只检查扩展名、退出码或文件存在。通常运行 ffprobe；验收样本完整解码。日常完整解码可作为可选严格校验，不能把未做完整解码写成已做。
11. 仅限有限时长视频/音频。本轮不默认加入无限直播录制，遇到直播应提示当前能力或要求有界时长。

### 4.3 图片和绘本

发现 src/srcset、lazy-load、明确原图链接和页面嵌入元数据中的候选；保留原始响应字节，探测实际像素与类型。同一逻辑图片优先明确原图或更高分辨率的同内容版本。不要全局盲删 URL 的压缩/尺寸参数，避免破坏签名或拿到不同资源。

同组必须有可靠证据：同一元素的 srcset 可作为线索，但 picture/art direction、不同裁切、语言和水印版本不能仅凭尺寸合并。无法确定时分别保存并标注关联不确定。缩略图和最佳版本之间保留关系；绘本页序独立于并发下载完成顺序，不重复算页，不丢页。来源未提供原图时如实显示当前可获取最大图片，不做 AI 放大。

### 4.4 文档和音频

PDF/PPT/DOC/EPUB/压缩包等按原件保存，不给文档统一贴“1080p”标签；扫描 PDF 可显示逐页像素信息但不得虚构整体画质。PPTX 原件和 PDF 预览不能按体积比较后互相替代；同时存在时可分别保存并关联。

音频优先可获取的原始高质量音轨；参考编码、声道、采样率与来源元数据，不以高码率跨编码绝对排序。不得把有损音频转 WAV 后声称无损源。语言选择优先于码率。

### 4.5 存储、超时与下载质量冲突

用户明确设置的单文件、任务、全局存储限制优先于画质；缺省限制须在界面可见。已有默认 100 MB/500 MB 不能暗中移除，也不能无声改变旧用户预算。

若预算迫使选用更低档，写明“受存储上限限制”，不要说“网站无高清”。若用户坚持最高档且不允许降级，返回可操作提示；增加预算由用户决定。大小未知时仍按流式字节计数限制；预算包含分离轨道、合并临时文件、字幕和重试残片。检查磁盘剩余空间，失败清理遵循原件保护规则。

媒体总时长上限应成为可配置任务选项，并与请求超时分开。先保留历史 600 秒兼容值，在 UI 可见地允许增加；新默认值如需调整，记录理由、边界和迁移方式，不能无限等待。

交互示例：

- 存在 4K 且成功：`已保存 · 3840×2160 · 当前最佳可用`。
- 1080p 受该账号权限限制、720p 成功：`已保存 · 1280×720 · 已降级`；详情解释权限依据。
- 仅发现 480p：`已保存 · 854×480 · 当前发现的最佳版本`；不显示“高清”。
- 高质量超预算：`已保存 · 1280×720 · 受 100 MB 上限限制`，可调整后重试。
- 无法探测尺寸：`已保存 · 质量未验证`；不杜撰像素。
- 代理失效：`任务失败 · 代理不可用，未切换直连`。

中文/英文标签、帮助、阶段、降级原因均有 i18n 键。原始诊断日志可保留英文，主提示应本地化。键盘操作、焦点可见、标签关联、颜色以外的状态文本必须具备；错误出现时焦点可到相关字段，不重置用户输入。1440 px、768 px、390 px 验证；移动端可横向滚动表格但整页不得溢出，常用质量控件不埋在高级折叠区域。

本轮交付的是文字设计规格，不声称已有高保真稿、交互原型或新 UI 验证结果。实施时以当前工作台截图/实际页面为基线检查布局，不擅自引入新视觉风格。

## 6. 数据与 API 合同（建议，实施前核对）

新增 `quality_policy`：best_available/cap_1080/cap_720/data_saver；`fallback_enabled`；`max_format_attempts`（建议默认 5、有硬上限）；`media_timeout_seconds`。旧 `media_quality` 保留兼容层：best → best_available，low → data_saver。新旧字段同时提供且冲突时返回明确 422，不猜测。请求都未提供时读取持久设置；新任务记录最终解析后的全部策略快照。

历史任务缺少新字段：显示“旧版策略/质量未记录”；不补写未经验证的质量。历史重试默认复制历史实际策略，允许用户明确改为新策略。不要批量重下载已有低清资源。设置只影响以后创建的任务。

候选及资源建议新增字段：

```json
{
  "quality": {
    "requested_policy": "best_available",
    "selection_state": "best_verified",
    "selection_basis": "extractor_formats_and_post_download_probe",
    "width": 1920,
    "height": 1080,
    "fps": 30,
    "video_codec": "h264",
    "audio_codec": "aac",
    "duration_seconds": 120,
    "estimated_size_bytes": null,
    "actual_size_bytes": 12345678,
    "format_ids": ["video-id", "audio-id"],
    "fallback_reason": null,
    "validation": {"probe": "passed", "full_decode": "not_run"}
  }
}
```

上例为合同示例，不是测试证据。selection_state 至少支持 best_verified、best_discovered、fallback、unknown；高清档位与状态分离。候选列表/尝试记录可以放独立表或结果对象，不必暴露新顶层服务。状态包含 no_hd_source、format_unavailable、access_restricted、size_limit、merge_failed、protocol_disallowed、quality_unknown 等原因码及本地化主文案。实际文件哈希不等于源文件哈希：无损合并也会改变容器字节，标记为 source_streams_remux，原始直链文件为 source_file，绝不混淆。

保留来源页面与受保护的资源解析信息，但持久化、导出和日志不得泄露 Cookie、Authorization 或签名地址中的凭据；候选元数据不能直接原样 dump 到公共日志或仓库。完整临时媒体地址按敏感配置处理，明示可能过期。

## 7. 技术实现边界与风险控制

1. 分离发现、候选排序、下载尝试、验证和登记职责；优先在现有模块中小幅重构，可新增 `quality.py` / `media.py`，不同时重写整个调度系统。
2. 复用 yt-dlp、FFmpeg/ffprobe 和现有 HTTP/Playwright 组件。先核对已安装版本与参数，再锁定依赖。更新前运行旧测试，升级后运行专项测试。
3. 探测与失败重试共用任务会话、代理和限速；不能新增未经控制的联网子进程。FFmpeg 默认只处理已下载本地轨道；若输入列表可能引用远程分片，拒绝或严格限定协议，不能无意绕过代理。
4. 仅调整 `-f` 不足以交付；`--max-filesize` 对未知大小流媒体也不是可靠完整配额。应用层监控最终文件及临时占用。
5. 服务器返回成功状态不证明文件完整；部分分片、只有字幕、只有音轨、截断 MP4 均应被专项识别。验证失败的文件不可被资源库当完整视频使用。
6. 大图解码限制像素和内存；探测媒体限制进程时间和输出大小；下载与 CPU 校验并发分别限制，防止 UI 卡死。
7. 不自动升级画质所需会员、付费 API 或代理；不关闭 TLS 校验；不启用陌生插件来规避权限。不能为了高清牺牲原有安全条件。
8. 文件命名处理 Windows 保留字符、重复后缀、路径穿越；取消或失败只清理当前任务拥有的临时文件，不删除已提交原件。
9. 现有技术债必须在最终报告列出：HTTP 跨重启字节续传、全局哈希去重、完整网络泄漏审计、真实会员站验收、翻译准确性。它们属于原有长期目标，不能因本轮高清功能发布就标成已完成；与新增质量逻辑直接相关的回归必须修复。

## 8. 验收矩阵

测试素材应为自有、明确允许测试或正常公开可获取资源。测试夹具可以确定性生成，但必须配合不同真实网站；不能把低清源下载成功当作高清选择正确。

| 场景 | 通过条件 |
|---|---|
| 新任务不填质量 | API 和 UI 均按默认最佳策略执行，表单清楚显示预算 |
| 同一内容 4K/1080p/720p | 无约束时选可获取最高质量；ffprobe 结果匹配；不是只选第一个 MP4 |
| 仅有 480p | 成功保存 480p，并说明来源/发现范围，无高清徽标 |
| 顶级格式链接失效 | 同候选有界刷新或重试，仍失败再转下一档；记录完整原因 |
| 429/临时 5xx | 尊重退避，不立即降档，不无限重试 |
| 格式权限限制 | 只在确有公开/授权较低候选时尝试；不绕过会员，不把整个会话失效当成画质问题 |
| 超单文件或剩余预算 | 保留限制、明确预算原因；无合规候选则受限结束，不伪装无高清源 |
| 大小未知的 HLS/DASH | 超限中止并清理，缺失片段不登记完整媒体 |
| 分离音视频 | 合并成功，宽高/时长/正确音轨核对；只有字幕或单轨不能满足完整视频成功 |
| 无 FFmpeg / 合并失败 | 明确依赖或合并问题；允许策略内尝试可直接保存的完整格式，无假成功 |
| 严格代理中途关闭 | 探测、下载、重试均无直连回退；测 HTTP、浏览器及媒体路径，未测路径如实列出 |
| 图片 thumbnail/srcset/original | 同内容原图优先、原字节保存；不同裁切/不同页不误合并 |
| 中文绘本 | 原图可打开、页序不受并发影响、不重复/丢页；原 PDF 与派生内容清楚区分 |
| 中文课件 | PDF/PPTX 按实际原格式保存可打开；PDF 预览不充作 PPTX |
| 中文讲播视频 | 至少一个实际高清源完成选择、下载、完整解码和音轨核对；若找不到高清源，此项未验证而非通过 |
| 任意其他文件 | 原件保存能力没有因质量筛选被白名单化 |
| 中断、取消、重启、重试 | 任务有准确终态、没有误删已保存文件；历史结果保留 |
| 中英与响应式 | 四工作区、质量设置、结果原因、空/加载/失败状态一致；键盘与三个视口检查 |
| API / 升级回归 | 旧 low/best 请求与历史数据兼容，新字段冲突有清楚错误，原有测试全过 |

验收报告包括来源、版本、请求参数、候选证据、最终尺寸/编码/时长/音轨、大小、哈希、降级原因、验证命令和结果。真实测试至少覆盖多个域名与网页/图片/文档/视频，不以一个域名代替全部覆盖。抓取资料留本地，不上传仓库。
